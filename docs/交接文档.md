## 1. 这是什么

把 **DeepSeek Harness（dsh）** 的 Agent 能力接进 **Zotero 10.x**，做文献伴读：

- 在阅读器侧栏与论文对话（全文问答，带页码估算标注）
- 划选原文 → 一键「解释 / 翻译 / 通俗化 / 追问」
- 回答回写为 Zotero **子笔记**或 PDF **高亮注释**
- **会话**：条目会话（单篇）与独立会话（整个分类 → 多文献分析）
- 会话可挂载为附件，双击在 Zotero 内置查看器中打开

**数据不出本机**：插件只与本机回环地址上的 dsh 通信（`127.0.0.1:<port>`），
论文内容与模型调用都在用户自己的 dsh 里。

## 6. 三个必须知道的陷阱（都真实踩过）

### 6.1 `addon` / `ztoolkit` 不能在模块顶层裸引用

`src/hooks.ts` **顶层**若有 `addon.data.config…`，会在**打包产物求值期**执行，
而那一刻 `_globalThis.addon = new Addon()` **还没执行**（esbuild 把 hooks 排在 index 之前），
于是抛 `ReferenceError: addon is not defined` → `Zotero.<instance>` 永不赋值 →
插件在 `extensions.json` 里**仍显示 `active: true`** 却什么都不工作
（Zotero 的 `_callMethod` 吞掉 bootstrap 异常，`xpcom/plugins.js:264-267`）。

**规则**：顶层只放声明；`addon`/`ztoolkit` 一律在函数内或惰性 getter 里取。
`addon/bootstrap.js` 已在全局对象上定义这两个标识符（**必须同时有 getter 和 setter**，
因为产物自己会赋值）。

### 6.2 `undoAction` 只在"修改已有对象"时才需要

`xpcom/undoHistory.js` 顶部注释：只跟踪**已存在对象**的修改，
`save()` 仅对 **non-isNew** 记录 stageChange；只有改动没有动作标签的事务
**会在提交时被静默丢弃**。

- **新建**笔记/注解：不需要 `undoAction`（传了也没用）
- **修改**已有笔记（追加模式）：**必须**带，且取值必须是**真实存在的 Fluent 消息 ID**
  （Zotero 10.0.5 只有 `undo-action-edit-note`、`undo-action-add-tag` 等；
  `undo-action-new-note` / `-add-annotation` / `-edit-tags` **都不存在**）

### 6.3 RPC 参数必须包在 `args.request` 里

dsh 的 typert 描述符 `wire: "request"`。平铺会返回
`gateway/arguments-invalid: missing "request"`（HTTP 仍 200，错误在 `result.ok` 里）。
例外：`session/list` 的参数名是 `_request`。
**注意业务失败仍是 HTTP 200** —— 必须看 `result.ok`。

## 8. 排障速查

**插件没加载**（设置里没有 DSH-for-Zotero 这一页）：

1. `<数据目录>\dsh-for-zotero-panel.txt` 是否存在、修改时间是否刚更新？不存在 = 插件的 `startup()` 没跑
   > ⚠️ 早先的 `dsh-for-zotero-menu.txt` **已废弃**（工具菜单里已无本项目的项，菜单诊断失去意义）。
2. `extensions.json` 里有 `dsh-for-zotero@local.dev` 吗？没有 = **必须用界面重新安装**
3. `extensions\` 目录里同 ID 文件是否**只有一份**？（多份会被 Zotero 整个卸载）
4. 是否曾**强杀** Zotero？那会让 `extensions.json` 不一致并丢掉插件记录

**右键菜单项空白或消失**：菜单文案用纯文本 label（不依赖 Fluent），图标走内联 SVG +
`menuitem-iconic` 类（Zotero 凭这个类才留出图标位）。

**面板不出结果**：

1. `<数据目录>\dsh-for-zotero-panel.txt` 看故障
2. `<数据目录>\dsh-for-zotero-selfcheck.txt` 看最近的自检结论
3. 隔离运行时是否 `running`（设置页能看到）——**端口由运行时给出**，不是设置项
   > ⚠️ 已无"共享模式"：不会再回退连接桌面版实例。未就绪时插件会明确报错。

**401**：多为 dsh 宿主重启后旧 cookie 失效。插件已能**自愈**（重读凭据重签重试一次）。
cookie 名 = `sha256(authority)`，因此签名用的 authority 必须与请求的 Host 头一致。

## 9. 会话模型（相对独立的一块）

会话**不**是 Zotero 条目类型 —— 实测 Zotero 不为插件提供自定义条目/附件类型
（`itemTypes.js` 只有读取接口，插件 API 只有 `itemPane` / `itemTree` / `menu`）。
会话记录存在插件数据目录的 `sessions.json`，正文由 dsh 保存。

但"挂载"可以借**真实附件形态**实现。Zotero 附件只有 5 种链接模式
（`attachments.js`：`IMPORTED_FILE=0` / `IMPORTED_URL=1` / `LINKED_FILE=2` /
`LINKED_URL=3` / `EMBEDDED_IMAGE=4`）。

### ⚠️ 现在只有**一种**形态（2026-10-05 修订）

| 形态                 | API                                | 打开行为                                                                                                |
| -------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------- |
| **网页链接**（唯一） | `Zotero.Attachments.importFromURL` | 打开**插件自己的会话页** `chrome://…/session.xhtml?session=<id>`，Zotero 内置查看器承载，**可继续对话** |

**已删除的三种**（连同 `sessionMount` 偏好一起）：

| 曾有的形态                | 为何删除                                                                                                                                         |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 文件链接 `linkFromFile`   | 页面来自 `file://`。实测 dsh 的 RPC **不返回 CORS 头**，带 `Origin: null` 的请求直接 403 —— 而 `file://` 的 Origin 正是 `null`。**只能看不能问** |
| 文件 `importFromFile`     | 同上                                                                                                                                             |
| 子笔记 `new Item("note")` | 纯文本入口，同样不能对话                                                                                                                         |

> 用户要求"只保留目前的方案"。选择项留着只会让人选到"看着一样、实际不能对话"的形态。
> `mountMode()` 现在固定返回 `web-link`，`writeSessionPage()` / `sessionPagePath()` /
> `mountSessionWithMode()` 已随之删除 —— 因此工作区里**不再产生** `session-*.html`。

### 会话工作区

- 条目会话 → `<DSH_HOME>/dsh-for-zotero/item-<条目key>`
- 独立会话 → `<DSH_HOME>/dsh-for-zotero/collection-<分类key>`
- **阅读器面板与会话共用同一目录**（去冗余：此前两处各写一份，同一文献被提取两遍）
- 写入内容：`README.md`、`meta.json`、`paper.txt`（或分块）、独立会话另有 `collection.md`

> ⚠️ 路径里**不含 sessionId**：dsh 会话的 `cwd` 在 `session/create` 那一刻固定、
> 事后无法更改，所以工作区必须按"范围"确定。这里踩过坑（曾用 `pending-<时间戳>`
> 占位，导致记录路径与实际工作区不一致）。

## 10. 沙箱里读不到子进程的 stdout（重要，踩过多次）

**结论：`Subprocess.sys.mjs` 拉起的子进程，其 stdout 管道在 Zotero 沙箱里拿不到数据。**

实测（同一台机器、同样的参数）：

| 启动方式                                           | stdout                                  | stderr    |
| -------------------------------------------------- | --------------------------------------- | --------- |
| PowerShell `Start-Process -RedirectStandardOutput` | 2 秒内 83 字节，含 `dsh web: …?token=…` | 1179 字节 |
| 插件（`Subprocess.call`，`stdout: "pipe"`）        | **85 秒仍为 0 字节**                    | 1179 字节 |

`stderr` 能读、`stdout` 读不到，所以**不是**"宿主打印慢"，而是那条通道不可用。
曾据此误判为"启动审计慢"，把超时从 45 秒放宽到 150 秒 —— 方向是错的。

**解决方式**：`host-launcher.mjs` 代理（源码内嵌在 `src/dsh/hostLauncher.ts`，
准备阶段落盘到 `<root>/host-launcher.mjs`）。代理 spawn 宿主、转发其输出、
把带 token 的 URL 写进 `<root>/launch-url.txt`，插件读文件。
实测**2 秒**拿到 URL，且 `GET /?token=…` → 200、同会话再 `GET /` → 200（可交互）。

代理必须在启动时**先清空**该文件，否则会读到上一次运行的陈旧 token。

> ⚠️ 内嵌脚本用**模板字符串**，不要改成普通引号：普通引号里的 `\n` / `\/` / `\.`
> 需要双层转义，落盘时还要还原 —— 实测写错过一次（生成的脚本里出现真换行，
> `node --check` 直接报错）。模板字符串里除反引号与 `${` 外都按字面处理。

### token 无法绕过

- `Set-Cookie` 带 **`HttpOnly`** → 页面脚本没法自己装会话；
- `processLaunchToken` 是**每进程随机**（`randomBytes`），无环境变量入口；
- `Services.cookies.add` 在本机 **9 种参数形态全部失败**，所以也没法替浏览器装 cookie。

即：`launch-url.txt` 里的 URL 是进入网页界面的**唯一**通道。

## 11. Zotero 菜单：不要用 MenuManager 建自己的项（踩了六轮）

**结论：会话菜单改为自己往 `#zotero-itemmenu` / `#zotero-collectionmenu` 插 DOM。**
设置页里的自检一直是这么做的、也一直正常 —— 有先例时优先复用。

### `MenuManager.registerMenu` 的三个坑（都实测过）

| #   | 事实                                                                                                                 | 后果                                             |
| --- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| 1   | **不认 `label`** —— `menuManager.js` 里 `"label"` 只出现在**一行注释**中                                             | 传 label 的菜单项**没有文字**                    |
| 2   | 加的类是 `_key = "zotero-custom-menu-" + 随机串`（`:273`），`menuID` 只进 `_mainKey`，且 `_key` 每次校验**重新生成** | 按 menuID 拼类选择器**永远匹配不到**             |
| 3   | 即便用通用类 `.zotero-custom-menu-item` 找到并补 `label`                                                             | 仍不显示，且该项**点了没反应**（command 没接到） |

### 菜单项图标要生效，三个条件缺一不可

1. `list-style-image` 有值（内联 + 注入 `!important` 规则双保险）；
2. 元素带 **`menuitem-iconic`** 类 —— Zotero **按类判断"这一项有图标"** 并预留绘制空间
   （`menuitem:not([checked=true],[icon],.menuitem-iconic)` 那条规则）。
   **只设 `list-style-image` 而不加这个类 → 没有位置可画** ← 这就是反复"看不到图标"的原因；
3. 图标地址能加载。**PNG 文件路径没成功**，改为**内联 SVG data URL**（16×16、`fill="context-fill"`）后可行。

编码注意：data URL 用**转义引号**（`"` → `'`）而不是 `encodeURIComponent`（后者会把引号变成 `%22`）。

### 排查这类问题的正确顺序（血泪）

**先取证，再改代码。** 判断图标/样式类问题时，一次取回这三项即可定位：

- `new Image()` 试加载 URL → **资源问题**还是样式问题；
- `getComputedStyle(el).list-style-image` → 是否被覆盖；
- 元素渲染尺寸 → 是否**没给图标留空间**。

反面教材：图标连续多轮不可见，我每轮都只是"改实现 → 等结果"，**从没取过运行时数据**；
而把这套取证加上之后，**一轮就定位到缺 `menuitem-iconic`**。
（实现见 `sessionPane.ts` 的 `diagnoseMenuIcon`，日志前缀 `图标取证`。）

> 另有两个自伤教训：诊断日志必须**每一步独立 try/catch** ——
> 我原本整段共用一个 `try`，结果"计算样式"那步抛错把同段里"URL 加载成功"的诊断也吞了，
> 让我误以为资源有问题；以及**改完必须立刻重跑构建** ——
> 一次留下重复的函数定义、构建直接报错，而我继续往下做了两轮才发现。

## 12. 已知限制（不是缺陷）

| 项                        | 说明                                                                                                                                                                                                                                                                 |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **无逐字流式**            | WebSocket 握手只能带 cookie 罐里的 cookie，而 Gecko 140 的 `Services.cookies.add` 参数形态试遍 9 种均失败（`NS_ERROR_ILLEGAL_VALUE`）。**面板改为轮询 + 分块显示**，约 1–2 秒出结果。ChromeWorker 本身已验证可用（构造/执行/WebSocket 均正常），卡点只在 cookie 罐。 |
| **页码是估算值**          | Zotero 的 `.zotero-ft-cache` 不含页边界，插件与提示词都明确标注"估算"。                                                                                                                                                                                              |
| **不打包 dsh 运行时**     | 体积与沙箱限制；dsh 需用户自行安装运行。                                                                                                                                                                                                                             |
| **桌面版 profile 被独占** | `dsh plugin` 装不进桌面 profile；二期 dsh 侧组件需自建 profile。                                                                                                                                                                                                     |
| **不改 dsh**              | 项目自我约束；因此不通过修改 dsh 来换取流式。                                                                                                                                                                                                                        |
