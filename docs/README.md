## 顺带一提：这个项目踩过的"文档类"坑

写在这里是因为它们**会重复发生**，而新来的人最容易被它们绊倒：

1. **写给 Agent 看的文案，会被 Agent 当作事实依据。** 工作区 README、
   `collection.md`、工具说明里写错一句，它就会照着答错 —— 而**构建、类型检查、
   单元测试都不会报错**。真机上因此让 Agent 说过"这个会话读不了正文"、
   "源码在 `runtime\` 下"之类的话。改动这类文案时请同时更新
   `test/unit/workspaceDocs.test.mjs`。

2. **面向用户的文件名必须与实际写入的名字一致。** 项目曾经同时写两个自检文件
   （名字只差一个 `last-`），而所有界面文案只提其中一个 —— 另一个对用户完全隐形。

3. **代码注释里的函数名/路径会腐烂。** 建议改代码时顺手搜一下注释里有没有引用它。
   （本项目靠 `tools/` 里的临时脚本核对过一轮，那类脚本没有留在仓库里。）
