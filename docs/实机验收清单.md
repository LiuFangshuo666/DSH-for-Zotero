# 实机验收清单（Zotero 10.x）

> 用途：本清单用于在**真实 Zotero** 里逐项确认。建议按顺序做，每步都给出"应该看到什么"与"不对时把什么发给我"。
>
> 验收前：把 `dsh-for-zotero.xpi` 装进 Zotero 10，**完全退出并重启** Zotero。
> 之后每次换新版 xpi 都要重启（Zotero 不会热加载已安装的 xpi）。
>
> **最后更新 2026-10-05**：已按当前实现修订 —— 只支持隔离运行时、会话只挂网页链接、
> 设置页四节、自检在设置页、批量处理改为"用你自己的会话"。

---

## ⚠️ 先读这一节：插件"整块不加载"时怎么排查

如果**工具菜单里一项都没有**、**设置里也没有 DSH-for-Zotero 这一页**，
那问题不在文案，而在**插件根本没被加载**。按下面顺序查（2026-10-02 实际踩过一遍）：

### 判据一：诊断文件存不存在

```
%USERPROFILE%\Zotero\dsh-for-zotero-panel.txt
```

- **文件存在且在增长**（看修改时间）→ 插件已加载，问题只在菜单注册/文案（把内容发我）。
- **文件不存在** → `hooks.onMainWindowLoad` 从未执行，即插件的 `startup()` 没跑起来。
- 文件第一行附近应有 `插件启动于 <ISO 时间>（feature: …）` —— 拿它的时间与 xpi 的修改时间
  对比，就能判断**跑的是不是新版**。

> ⚠️ 早先用的是 `dsh-for-zotero-menu.txt`（工具菜单诊断）。**那个文件已废弃、不再写入** ——
> 因为工具菜单里已经没有本项目的项了，菜单诊断失去意义。别再照它排查。

### 判据二：`extensions` 目录里同一个插件有几份

```
%APPDATA%\Zotero\Zotero\Profiles\<profile>\extensions\
```

❗**这是最容易踩的坑**：Zotero/AddonManager **按文件名解析插件 ID**，
所以 `dsh-for-zotero@zotero.cn.xpi.bak-20261002-205547` 解析出的 ID
**同样是 `dsh-for-zotero@zotero.cn`**。同一 ID 在目录里出现多份时，
Zotero 会在启动时把插件**整个卸载**（删掉 xpi，并从 `extensions.json` 抹掉记录）。

**该目录里必须只有一份主文件**，备份要放到 extensions **之外**
（例如 `%APPDATA%\Zotero\Zotero\plugin-backups\`）。

### 判据二之补充：**不要再"直接往 extensions 目录拷 xpi"来安装**

2026-10-02 用**受控实验**确认（`tools/test-plugin-registration.ps1`）：

| 步骤                                 | 结果                                    |
| ------------------------------------ | --------------------------------------- |
| 基线：目录里**没有**该 xpi → 启动    | `extensions.json` 无记录 ✅（对照成立） |
| 把 xpi 放进 `extensions\` → 再次启动 | `extensions.json` **仍无记录** ❌       |

**结论：Zotero 10 不会自动登记手工放进 `extensions\` 的文件。**
（早期几次"看起来成功了"，是因为此前用界面装过一次，记录仍在库里。）

**唯一可靠的安装方式是 Zotero 自己的界面**：

```
工具 → 插件（Add-ons）→ 齿轮图标 → Install Add-on From File… → 选 dsh-for-zotero.xpi
```

> **强制重装的可靠步骤**：
>
> 1. **用 `CloseMainWindow()` 正常退出 Zotero 并等它退干净** ——
>    ⚠️ **绝不要用任务管理器/`Stop-Process -Force` 强杀**。强杀会让它来不及写完
>    `extensions.json`，并留下 `.startup-incomplete`；
>    下次启动会因为这份不一致的插件数据库**丢掉插件记录**（文件还在，但不加载）。
>    这个坑在 2026-10-02 反复触发了三次。
> 2. 删掉 `extensions\dsh-for-zotero@zotero.cn.xpi`；
> 3. 启动 Zotero（让它以"无此插件"的干净状态启动一次并写完 `extensions.json`）；
> 4. 退出 Zotero；
> 5. **用上面的界面方式重新安装**。

**判断"启动是否真的完成"**：看 `%LOCALAPPDATA%\Zotero\Zotero\Profiles\<profile>\.startup-incomplete`
是否消失。`extensions.json` / `addonStartup.json.lz4` 只在启动流程**后段**落盘，
启动早期去读它们会误判。

**验证插件是否真的被加载**（最直接的三个判据）：

1. `<数据目录>\dsh-for-zotero-panel.txt` 的修改时间是否刚刚更新；
2. `addonStartup.json.lz4` 里是否含 `dsh-for-zotero`（AddonManager 的启动记录）；
3. Zotero 日志（`-ZoteroDebugText`）里是否有 `Calling bootstrap method 'startup' for plugin dsh-for-zotero@zotero.cn`。

### 判据三：`extensions.json` 里还有没有我们的记录

```
%APPDATA%\Zotero\Zotero\Profiles\<profile>\extensions.json
```

用编辑器搜 `dsh-for-zotero@zotero.cn`：

- **搜得到** → 插件已注册（`"active":true`、`"appDisabled":false` 是正常状态）。
- **搜不到** → 插件已被 Zotero 卸载，回到判据二检查目录是不是有多份。

### 为什么"文件被删了"却看不到报错

Zotero 的 `bootstrap` 方法调用是**吞异常**的（`xpcom/plugins.js:257-267`）：
出错只写进 `Zotero.logError`，插件在 `extensions.json` 里**仍然显示 `active: true`**。
所以"插件显示已启用、却什么都不工作"是正常的失败形态，必须靠上面三条判据区分。

## 0. 前置：隔离运行时是否就绪

> 插件**只使用自己拉起的隔离实例**（独立 `DSH_HOME`、独立端口、独立凭据）。
> 桌面版 Harness 只需**装在本机**供提取运行时用，**不需要**手动启动、也不需要在插件里填端口。

| 检查             | 怎么查                                                    | 期望                                          |
| ---------------- | --------------------------------------------------------- | --------------------------------------------- |
| 本机装有 Harness | `E:\deepseek harness` 之类安装目录存在                    | 存在即可（首次提取约 330 MB）                 |
| 运行时状态       | 编辑 → 设置 → DSH-for-Zotero → **隔离运行时**             | 状态显示 `running` 与端口（默认 19400）       |
| 启动进度         | 重启 Zotero 后看进度窗口                                  | 会显示"正在准备/启动 DSH…"，就绪后自动关闭    |
| 隔离凭据         | `<Zotero 数据目录>\dsh-for-zotero\home\.credentials.yaml` | 存在即可（插件只合并模型记录，不打印 secret） |

> ⚠️ 运行时**未就绪时插件会明确报错**（不会退回连接桌面版实例）——
> 这是刻意的：退回会让凭据与会话串到另一个实例上。

## 1. 右键菜单与设置界面

1. 在文献库界面**右键一个分类** → **应看到**带图标的「新建独立会话」。
   右键一个条目 → **应看到**「新建会话」。
   > **工具菜单里不再有任何本项目的项**（自检已移入设置页）。
2. 打开 **编辑 → 设置 → DSH-for-Zotero**。
   - **应看到四节**：`隔离运行时` / `自检` / `阅读器侧栏面板` / `高级`，各控件有中文说明。
   - ❗若某项**没有说明文字**，说明对应的 Fluent 条目没解析（曾因文案里写了 `{}` 而整条失效）。

**不对时发我**：右键菜单是否出现项与图标、设置页哪一项缺说明。

## 2. 自检

**编辑 → 设置 → DSH-for-Zotero → 自检 → 运行自检**。逐项对照：

| 检查项         | 期望结果                                                                                                            | 说明                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 沙箱能力       | `crypto.subtle` / `fetch` / `XMLHttpRequest` / `ChromeWorker` / `Services.cookies` 均为可用；`WebSocket` 显示不可用 | 不可用是**预期**的，走 worker                                           |
| 运行时配置     | `DSH_HOME` 指向隔离目录、`authority=127.0.0.1:<隔离端口>`                                                           | 若显示 `~/.dsh` 说明隔离运行时没起来                                    |
| 凭据读取       | secret 长度 43                                                                                                      | 非 43 说明凭据格式变了                                                  |
| cookie 签名    | 生成了 cookie 名与值长度                                                                                            | 值长度约 173                                                            |
| 投递通道       | `xhr-header` 或 `cookie-jar`                                                                                        | **若显示"没有可用的 HTTP 通道"** ⇒ 正是本轮修复的那类环境，请把整段发我 |
| `session/list` | HTTP 200 + 会话数                                                                                                   | 这是认证成功的关键证据                                                  |
| cookie 罐实况  | 成功或给出失败原因                                                                                                  | 成功 ⇒ 流式 WebSocket 才可能带上 cookie                                 |
| dsh 侧内容     | 未启用 / 已安装 / 已更新                                                                                            | 见第 7 步                                                               |

**不对时发我**：整段自检文本（可点"复制"），它同时写入 `dsh-for-zotero-selfcheck.txt`。

## 3. 自检（含流式实测）

这一步同时定案两件事：**cookie 罐能否写入**、**WebSocket 握手能否带 cookie**。

| 结果                                  | 含义                        | 后续                                                     |
| ------------------------------------- | --------------------------- | -------------------------------------------------------- |
| 流式实测 **成功**（收到 snapshot 帧） | 逐字流式可用                | 面板会逐字出结果                                         |
| 流式失败，但自检其余项 OK             | WebSocket 握手仍不带 cookie | 面板退化为"轮询分段显示"，**功能不受影响**，只是不是逐字 |

> 两种结果我都需要：**失败也是有价值的结论**。请把"传输方式"与"错误原因"两行发我。

## 4. 阅读器面板（M1–M4 主流程）

打开一篇有文字层的 PDF，右侧应出现 **DSH 伴读** 面板。

| 步骤               | 期望                                                                           |
| ------------------ | ------------------------------------------------------------------------------ |
| 面板打开           | 顶部状态栏显示端口与连接状态；下方有输入框                                     |
| 点 **速读摘要**    | 逐字（或分段）出**结构化**结果：一句话结论/研究问题/方法路线/主要结果/适用边界 |
| 输入自定义问题回车 | 正常回答；回答里页码被标注为**估算值**                                         |
| 点 **重新生成**    | 重发上一条问题                                                                 |
| 点 **新建对话**    | 开一条新会话；历史下拉里能看到之前的会话                                       |
| 历史下拉切换       | 能切回旧会话并看到内容                                                         |
| 生成中点 **停止**  | 立刻停在当前内容                                                               |

**不对时发我**：面板截图 + 状态栏文字 + Zotero 日志里的 `[DSH]` 行。

## 5. 划词伴读（M2/M4）

在 PDF 里划选一段文字。

| 检查                       | 期望                                                                   |
| -------------------------- | ---------------------------------------------------------------------- |
| 选区弹窗                   | 出现 Zotero 原生弹窗，且**多出四个按钮**：解释 / 翻译 / 通俗化 / 追问  |
| 点 **解释**                | 面板开始回答，回答围绕**划选的那段原文**                               |
| 回答后点 **存为笔记**      | 回到条目看子笔记：标题为 `DSH 伴读 - 日期`，内容含问题、原文引用、回答 |
| 再点一次 **存为笔记**      | **追加到同一条笔记**（不会新建第二条）                                 |
| 划词后点 **存为高亮**      | PDF 里出现高亮，评论是 AI 回答                                         |
| **没有**划词时看"存为高亮" | **灰掉不可点**，悬停提示"需要先在阅读器里划选文字"                     |

> ⚠️ **存为高亮依赖选区几何信息**（`rects`）。我尚未在真机核实弹窗载荷里这个字段叫什么名字，
> 代码用宽松探测。若按钮**一直灰着**，请把 Zotero 日志里 `[DSH]` 相关行发我 —— 我需要那个字段名。

**撤销验证**：`Ctrl+Z` 应能撤销刚才写入的笔记/高亮（写库都带了 `undoAction`）。

## 6. 多文献分析（原「批量处理」——**已改为用你自己的会话**）

> ⚠️ 插件里**没有批量处理功能了**（`src/batch/*`、`batchDialog.ts` 与相关偏好文案已整体删除）。
> 多文献任务现在**由你的 dsh 会话完成** —— Agent 有完整的 Zotero 工具。

1. 在文献库界面**右键某个分类 → 新建独立会话**（工作区就是这个分类）。
2. 在会话里直接说，例如：
   > 把这个分类里的论文做成一张对比表：每篇一行，列出方法与主要结论。
3. 它会用 `search` / `listItems` / `getFullText` 自己读，产出结果写到工作区文件里。

| 检查                 | 期望                                                                                             |
| -------------------- | ------------------------------------------------------------------------------------------------ |
| 会话能读到整个分类   | Agent 能列出分类里的条目（`listItems`）                                                          |
| 能读论文原文         | `getFullText` 返回正文（扫描件会明确说明"没有文字层"）                                           |
| 写操作直接生效       | 让它"给某篇加个标签"，条目上立刻可见，`Ctrl+Z` 可撤销                                            |
| **结构性改动需确认** | 让它"新建一条条目"或"删掉某条"→ 会话页顶部出现黄色角标「有 N 项改动等你确认」，点开逐条确认/忽略 |
| 确认后才执行         | 未确认前条目**不存在**（新建）/ **还在**（删除）                                                 |

**不对时发我**：会话页顶部角标的展开内容 + 诊断文件里 `新建条目待确认` / `已新建` 那几行。

## 7. dsh 侧内容安装（可选）

默认**不写**你的 dsh 目录。想启用：

1. **设置 → DSH-for-Zotero → 高级**：勾选"安装伴读 skill"和/或"写入常驻指令"。
2. 到同一设置页的 **自检** 节点「运行自检」（自检里会执行同步）。
3. 检查文件（注意是**隔离实例**的 DSH_HOME，不是 `~/.dsh`）：
   - `<Zotero 数据目录>\dsh-for-zotero\home\skills\dsh-for-zotero-reading\SKILL.md`
   - `<Zotero 数据目录>\dsh-for-zotero\home\AGENTS.md`（新增一个带 `<!-- DSH-for-Zotero:begin -->` 标记的块）
4. 在会话里问一句："读一下我刚放进来的这篇论文" —— 应能感到它按 skill 的套路走。
5. **取消勾选 → 再跑自检**：上述 skill 文件被删除；`AGENTS.md` **只删掉我们的标记块**，
   你原有的内容必须完好。❗这一条请重点确认，因为它动的是你自己的文件。

## 8. 回滚

- **不要**把备份文件留在 `extensions` 目录里（会导致插件被整个卸载，见开头那一节）。
  备份统一放在 `%APPDATA%\Zotero\Zotero\plugin-backups\`。
- 回滚做法：把备份文件复制回 `extensions\`，并确保**只留这一份**、文件名为
  `dsh-for-zotero@zotero.cn.xpi`，然后重启 Zotero。
- 想彻底移除 dsh 侧内容：取消第 7 步两个勾选并跑一次自检。
