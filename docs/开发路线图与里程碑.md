## 1. 推进原则

1. **每个里程碑结束都产出可安装的 `.xpi` 并实机验证**，不留"写完一堆代码再一起调"。
2. **桥接链路已真机跑通**（协议文档 §8.1：认证 + 会话创建 + WebSocket + 逐字流式全部实测通过），所以 M0 不是探路，而是**把已验证的链路搬进 Zotero 并解决插件沙箱的三个限制**。
3. **风险前置**：M0 必须定下"HTTP 怎么带 cookie"与"WebSocket 走哪条路"；这两点没结论就不写 UI。
4. 每个里程碑交付：改动清单 + 安装方法 + 验收步骤 + 已知问题。

### 2.3 我尝试过、但被环境挡住的一步（如实记录）

我本想自己先验证"插件能被 Zotero 正常加载"，做法是：建一次性 profile → 把 xpi 解包到 `profile/extensions/<addonID>/` → 用 `zotero.exe -profile <dir> -datadir <dir>` 启动 → 查 `extensions.json`。

结果：**Zotero 在这套沙箱里无法完成启动**——进程确实在跑（3 个 zotero 进程、占 384MB 内存、CPU 有活动），但 profile 里始终停在 `.startup-incomplete`，`extensions.json` 从未生成，stdout/stderr 全空，也没有窗口标题。尝试了带/不带 `-no-remote`、`-ZoteroDebugText`、重定向日志、等待 60 秒以上，均无进展。同时确认：启动期间插件目录**从未被读取**（文件时间戳未变），profile 里除我自己写的 `user.js` 外没有出现插件 ID —— 说明启动**根本没走到插件扫描阶段**，因此这不是插件的问题。

**结论**：加载验证必须在你自己（非沙箱）的 Zotero 里做。这也是为什么 §2.2 的三项只能由你确认。

### 2.4 M0 待你在真实 Zotero 里确认的 3 件事

装完 xpi 后跑 **工具菜单 → DSH 自检**（想看流式就点"含流式实测"），把输出贴回来即可定案：

| #   | 待确认                                                                                    | 现状与回退                                                                                                       |
| --- | ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 1   | 插件里 `fetch` 是否被 dsh 的信任检查拒绝（403）                                           | 源码上"不带 Origin 即放行"；若被拒 → 带同源 `Origin` 或改走 XHR 通道                                             |
| 2   | `Services.cookies.add` 的可用签名（9/10/11 参）                                           | 该接口在 C++ 层、源码不在 `omni.ja`，无法静态核对；代码已按参数从多到少尝试，全失败自动回退 XHR 显式 `Cookie` 头 |
| 3   | WebSocket 能否经 `ChromeWorker` 建立（沙箱内**无** `WebSocket`，但注入了 `ChromeWorker`） | 代码已实现三级回退；若 worker 加载 `chrome://` 脚本失败则依次试主窗口、轮询                                      |

## 3. 各里程碑详细任务

### M0 · 桥接移植 + 沙箱限制定型

**M0 要解决的三个已知限制**（均已从 Zotero 源码核实，见 `zotero10-plugin-fs-crypto-findings.md`）：

| 限制                           | 事实                                                                                                                                                                              | 方案                                                                                                                                                                                                                                                                       |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 插件沙箱**没有 `WebSocket`**   | `xpcom/plugins.js:141-156` 的 `wantGlobalProperties` 只有 `fetch`/`XMLHttpRequest`/`crypto`/… ，**无 WebSocket**；而翻译沙箱是显式要了 WebSocket 的（`TranslationChild.mjs:211`） | ① **首选**：把 WS 客户端放进注入的 `ChromeWorker`（`plugins.js:167`），worker 内有完整 Web API，用 `postMessage` 把帧传回主线程渲染；② 备选：主窗口 `new WebSocket()`；③ 兜底：退回 `session/page` 轮询                                                                    |
| **`Cookie` 是 fetch 禁止头**   | 规范层面禁止脚本设置 `Cookie`；Zotero 自己的做法是用 XHR 通道（`http.js:330-331` `forceAllowThirdPartyCookie`）                                                                   | ① **首选**：用 `Services.cookies.add(...)`（`Services` 已在沙箱内）把自签 cookie 写进 cookie 罐 → 之后普通 `fetch` **与** WebSocket 握手都会自动携带；② 备选：HTTP 侧走 `Zotero.HTTP.request`（XHR，可用 `setRequestHeader`）；③ 也可让 `ChromeWorker` 内的 fetch 承担请求 |
| 沙箱**没有 `AbortController`** | `plugins.js` 全文件无 AbortController                                                                                                                                             | 取消走 XHR 的 `abort()`；流式取消走 WS 的 `{"type":"cancel"}` 帧（协议本身支持）                                                                                                                                                                                           |
