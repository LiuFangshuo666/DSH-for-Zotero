## 2. 一期详细规格

### F1 阅读器 AI 伴读面板

**形态**：Zotero PDF 阅读器右侧的独立面板（`ItemPaneManager.registerSection`，`tabType === 'reader'` 时启用），与"批注/缩略图"等原生标签页并列。面板纵向分三段：顶部工具条、中部对话流、底部输入区。

| 编号 | 需求       | 说明与判定标准                                                                                                                                           |
| ---- | ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F1.1 | 上下文识别 | 打开某篇 PDF 时，面板标题显示该文献题名与年份；切换标签页时自动切换到对应文献的会话。识别失败（如附件无父条目）时降级为"独立附件"模式，仅用 PDF 自身文本 |
| F1.2 | 一键指令   | 五个内置按钮：**速读摘要**、**方法与创新点**、**结论与证据强度**、**术语与背景**、**局限与可质疑处**。点击后立即流式作答，无需用户输入                   |
| F1.3 | 自由对话   | 底部输入框支持多行、Enter 发送、Shift+Enter 换行；回答流式渲染 Markdown（公式与表格可接受降级显示）；提供"停止生成""重新生成""复制"                      |
| F1.4 | 会话管理   | 会话按 `itemID` 持久化，重开 Zotero 可恢复；支持新建、切换历史、清空；会话内显示消息时间与所用模型名                                                     |
| F1.5 | 引用溯源   | 回答中的事实性断言应尽量标注来源页码；一期采用"提示词要求 + 模型自报页码"，并在 UI 上明确标注"页码由模型给出，请核对"（不做硬性校验，避免过度工程）      |

**内置指令的输出结构约定**

| 指令           | 期望输出结构                                                      |
| -------------- | ----------------------------------------------------------------- |
| 速读摘要       | ① 一句话结论 ② 研究问题 ③ 方法路线 ④ 主要结果（带数据）⑤ 适用边界 |
| 方法与创新点   | ① 方法骨架分步 ② 相对已有工作的差异点 ③ 关键假设                  |
| 结论与证据强度 | ① 结论清单 ② 支撑证据类型（实验/仿真/理论/案例）③ 证据弱点        |
| 术语与背景     | 术语表（原文术语 → 中文 → 一句话解释）                            |
| 局限与可质疑处 | ① 作者自述局限 ② 读者视角的额外疑点 ③ 需要查证的点                |

### F2 划词伴读

| 编号 | 需求       | 说明                                                                                                                                          |
| ---- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| F2.1 | 浮出工具条 | 在 PDF 中划选文本后，于选区附近显示轻量操作条（翻译 / 解释 / 通俗化 / 追问 / 存为高亮）。工具条需避让选区、不遮挡文本，滚动或点击他处自动消失 |
| F2.2 | 快捷动作   | 每个动作发起一次带选区的独立请求，结果直接追加到面板对话流（而不是弹出新窗口），便于连续追问                                                  |
| F2.3 | 上下文注入 | 选区文本 + 所在页 ±1 页上下文（可配）一并送入；用户可在设置里选择"仅发送选区"以节省 token                                                     |

> 技术方案已核实（主文档 §3.4）：Zotero 10 **没有** `getSelectedText`，但提供官方插件事件 `Zotero.Reader.registerEventListener('renderTextSelectionPopup', handler, pluginID)`，事件对象为 `{ reader, doc, params, append }`，选中文本在 `params.annotation.text`。因此"浮出工具条"**不必自绘**：直接往官方选区弹窗里 `append` 我们的按钮即可，定位与避让由 Zotero 负责，可靠性显著更高。待确认的只有载荷中的页码字段（拿不到就按"无页码"处理）。

### F3 结果回写

| 编号 | 需求         | 说明                                                                                                                                                                      |
| ---- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F3.1 | 保存为子笔记 | 每条 AI 回答右上角"存为笔记"：在该文献下创建子笔记，标题自动生成（如 `AI 速读摘要 - 2026-02-14`），正文含问题、回答、所用模型、原文引用；重复保存时追加到同一笔记而非新建 |
| F3.2 | 生成高亮注释 | 对划词问答结果："存为高亮"在 PDF 上以指定颜色创建高亮，评论字段写入 AI 解释（可截断到合理长度）                                                                           |
| F3.3 | 复制/导出    | 复制单条或整段会话为 Markdown；整段会话可导出到剪贴板或保存为笔记                                                                                                         |

### F4 设置与 DSH 连接

**设置位置**：Zotero 设置 → 插件 → DSH-for-Zotero（`addon/content/preferences.xhtml`）。

> **与上一版方案的重要区别**：模型与凭据由 dsh 管理，**插件不再有 API Key / Base URL 设置项**（本机 dsh 已登录 DeepSeek 账号，模型默认为 `deepseek-flash`）。插件设置聚焦"连哪个 dsh、怎么给上下文、隐私边界"。

| 分组     | 设置项                             | 默认值                              | 说明                                                     |
| -------- | ---------------------------------- | ----------------------------------- | -------------------------------------------------------- |
| DSH 连接 | 端口                               | `19387`                             | 桌面版默认端口；另可填 `3080`（`dsh web`）。插件按序探测 |
|          | 认证方式                           | 自动（读凭据密钥自签）              | 备选"粘贴 dsh 启动 URL 中的 token"；"重新认证"按钮       |
|          | DSH_HOME                           | 自动检测（`$DSH_HOME` 或 `~/.dsh`） | 只读取 `.credentials.yaml` 的密钥字段，不写入            |
|          | 模型（只读展示）                   | 由 dsh 决定                         | 面板顶部显示当前模型名，来源 `session/modelCatalog`      |
| 上下文   | 全文供給方式                       | 路径引用（Agent 按需读）            | 备选"分块复制进工作区""仅元数据+摘要"                    |
|          | 分块大小                           | 40 KB                               | `read` 工具有 50 KiB/2000 行上限，故留余量               |
|          | 划词附带上下文页数                 | 1                                   | 0 = 仅选区                                               |
|          | 页码标注                           | 估算值 + 明确提示                   | 缓存全文无页边界，UI 必须如实标注                        |
| 生成行为 | 逐字流式                           | 开                                  | 关则等生成完整段再显示（用于诊断）                       |
|          | 请求超时（秒）                     | 120                                 | 超时给出可读错误                                         |
| 隐私     | 首次发送前确认                     | 开                                  | 首次把论文内容交给 Agent 时弹一次确认                    |
|          | 记录交互日志到本地                 | 关                                  | 写入插件数据目录，便于排查；含脱敏                       |
| 界面     | 语言                               | 跟随 Zotero                         | `zh-CN` / `en-US`                                        |
|          | 回答显示语言                       | 中文                                | 可设为"跟随论文语言"                                     |
| 高级     | 常驻指令写入 `$DSH_HOME/AGENTS.md` | 关                                  | 需用户显式同意才写                                       |
|          | 伴读 skill 安装                    | 关                                  | 需用户显式同意才写 `$DSH_HOME/skills/`                   |

**连接自检**：设置页提供"DSH 自检"按钮（等价于工具菜单命令），逐项反馈：端口可达、密钥可读、cookie 自签成功、`session/list` 返回会话数、WebSocket 握手与 `snapshot` 帧、Zotero 侧沙箱能力（`WebSocket` 可用性等）。

### 边界与异常处理（一期必须覆盖）

| 场景                                     | 期望行为                                                                                                              |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| **dsh 未启动 / 端口不通**                | 面板顶部状态条显示"未连接 dsh"，并给出一键复制的启动命令（桌面版或 `dsh web`）；禁用发送                              |
| **认证失败（401/403）**                  | 区分两类：cookie 失效 → 自动重签一次；密钥读不到 → 引导"粘贴 dsh 启动 URL 中的 token"                                 |
| **dsh 版本不匹配**                       | 用 `session/list` 与协议自检探测；不匹配时明确提示"本插件适配 dsh 0.2.0-rc.2，当前版本可能不兼容"，并给出复核清单链接 |
| 扫描版 PDF（无文字层）                   | 提示"该 PDF 没有可提取文本，可能是扫描件"，降级为"仅用元数据+摘要对话"                                                |
| PDF 未建索引                             | 触发索引并显示进度，完成前先用元数据对话                                                                              |
| 论文超长                                 | 走"路径引用/分块"策略；回答尾部注明本次基于哪些片段与页码（估算）                                                     |
| 生成中断 / 超时                          | 保留已生成内容，标记"生成中断"，提供"重试"                                                                            |
| 会话 cwd 冲突（`ApiSessionCwdConflict`） | 自动改为新建会话，并提示"原会话工作区已变化"                                                                          |
| 生成中途关闭面板或切换文献               | 发送 `{"type":"cancel"}` 并释放流；下次进入该文献可见已完成部分                                                       |
| 元数据缺失（题名/作者为空）              | 用文件名兜底，不阻塞对话                                                                                              |

## 3. 二期详细规格

### F5 批量处理

**入口**：文献列表右键菜单"AI 批量处理…" / 工具菜单。**形态**：独立对话框（ztoolkit DialogHelper）。

| 编号 | 需求           | 说明                                                                                                                         |
| ---- | -------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| F5.1 | 多篇对比表     | 选 2–20 篇 → 生成对比表：研究问题 / 方法 / 数据 / 指标 / 结论 / 局限。表格可预览、可复制为 Markdown/CSV、可保存为独立笔记    |
| F5.2 | 批量结构化笔记 | 对每篇生成统一模板笔记（摘要/方法/结论/可引用点），写入子笔记或指定分类的笔记条目                                            |
| F5.3 | 批量标签建议   | 为每篇建议 3–8 个关键词标签；**必须先在对话框中列出"文献 → 拟新增标签"清单**，用户勾选确认后才写入；写入操作支持 Zotero 撤销 |
| F5.4 | 任务队列       | 并发上限可配（默认 2）；显示总进度、单篇状态、已用 token 估算；支持暂停/取消；中断后可从已完成项继续（断点续跑）             |

**关键设计约束**

- **批量任务必须有"预览 → 确认 → 写入"三段式**，绝不静默修改库数据。
- **限流保护**：内置请求间隔（默认 1s）与退避策略，遇 429 指数退避。
- **成本可见**：对话框实时显示已发送请求数与字符数，给出粗略费用提示（按用户填入的单价，可选）。
- **幂等**：同一篇文献重复跑批不重复创建笔记（按标题指纹去重，冲突时询问"覆盖/追加/跳过"）。

### F6 库级问答与语义检索（默认关闭）

| 编号 | 需求         | 说明                                                                                                                                        |
| ---- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| F6.1 | 选区范围 RAG | 在选定分类或选定文献集合内提问，如"这批文献用的评价指标有哪些差异"                                                                          |
| F6.2 | 本地检索     | 一期先做关键词/BM25 检索（可用 Zotero 10 的 `fulltextContent` 条件）；二期评估本地向量索引（Transformers.js 或调用用户自备 embedding 服务） |
| F6.3 | 综述草稿     | 基于检索结果生成带引用的综述段落，引用以 Zotero item key 标注，便于回溯                                                                     |

> F6 不在一期，原因：全文索引/向量化在 Zotero 沙箱内做本地推理的成本与体积（模型权重）都不小，且一期的"单篇伴读"已能覆盖绝大多数使用价值。建议一期上线后按实际使用反馈决定。

## 4. 交互与视觉约定

- **面板宽度**：自适应容器，最小 260px；窄于此宽度时一键指令按钮折叠为下拉。
- **流式渲染**：以 30–60ms 节流批量刷新 DOM，避免逐 token 重排导致卡顿。
- **状态可见**：等待中显示三点动画与"正在检索片段…/正在请求模型…"阶段文案；错误用红色内联卡片而非弹窗。
- **按钮语义**：一次只允许一个进行中的生成；生成期间其他发送按钮置灰，"停止"变为可用。
- **可访问性**：所有按钮有 `title` 与本地化文本；键盘可达（Tab 顺序：工具条 → 对话流 → 输入框）。
- **主题适配**：使用 Zotero CSS 变量（`--material-background`、`--fill-primary` 等），自动适配深色模式。

## 5. 本地化

| 文件                                 | 用途                 |
| ------------------------------------ | -------------------- |
| `addon/locale/zh-CN/mainWindow.ftl`  | 面板、按钮、状态文案 |
| `addon/locale/zh-CN/preferences.ftl` | 设置项标签与说明     |
| `addon/locale/zh-CN/addon.ftl`       | 菜单、对话框、通知   |
| `addon/locale/en-US/*.ftl`           | 同上英文版           |

约束：**代码里不写死任何用户可见文本**，一律 `getString("key")`；提示词模板本身按其自身语言独立于 UI 语言（用户可在设置里覆盖）。
